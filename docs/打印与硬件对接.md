# 打印与硬件对接

## 三个打印入口

| 入口 | 路由 | 内容 | 默认 |
| --- | --- | --- | --- |
| 答题卡打印 | `/#/papers/print`、`/#/papers/{id}/print` | 答题卡正面 + 背面 | 双面 |
| 试卷 / 正反双面打印 | `/#/papers/bundle` | 当前统一试卷（正面 + 背面） | 双面 |
| 条形码标签打印 | `/#/papers/barcode` | 标签卷纸或 A4 双列 | 单张标签 |

打印页统一使用 CSS `mm` 尺寸和 `@page` 设置，屏幕预览缩放不影响实际打印尺寸。打印时选择：

- 缩放：100%
- 边距：无
- 背景图形：开
- 双面打印：短边翻转 / 长边翻转按打印机纸路选择

## 浏览器打印桥

所有打印按钮都走 `src/lib/print.ts` 的 `requestPrint()`。

它会：

1. 派发 `ocr:print` 自定义事件，携带可序列化的 `PrintJob`；
2. 如果事件没有被 `preventDefault()`，再调用 `window.print()` 打开浏览器打印对话框。

`PrintJob` 字段：

```ts
{
  kind: 'answer-card' | 'exam-paper' | 'barcode-label' | 'paper-bundle'
  title: string
  paperSize: string
  orientation: 'portrait' | 'landscape'
  widthMm: number
  heightMm: number
  pages: number
  doubleSided: boolean
  source: string
  createdAt: string
}
```

硬件桥接示例：

```ts
window.addEventListener('ocr:print', (event) => {
  event.preventDefault() // 不走浏览器打印对话框
  hardwareBridge.send(event.detail)
})
```

## 接硬件的现实边界

纯浏览器不能静默向 USB/网络打印机发送原始打印指令，现阶段有三种可行路线：

1. **浏览器打印对话框**：现在已可用，最稳，适合通用打印机。
2. **QZ Tray / 本地打印服务**：监听 `ocr:print`，通过 WebSocket 把 `PrintJob` 和渲染后的 PDF 交给本地服务打印。
3. **WebUSB / WebSerial**：只适合支持对应协议的标签机，需要用户授权；不能替代普通打印机。

后续如果接硬件，优先保留 `ocr:print` 事件作为统一入口，打印页负责生成标准尺寸 DOM/PDF，硬件桥只负责传输，不直接解析卡片 JSON。
