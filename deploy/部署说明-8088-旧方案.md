# 部署到 https://8.130.177.176:8088/ocr

## 一、上传什么

把 `deploy/ocr-8088.zip` 解压到服务器上当前 `/ocr` 站点对应的目录（该目录下现在已有旧的
`index.html`、`assets/`、`favicon.svg`）。

- 站点根目录建议：`/var/www/ocr/`
- 解压后目录结构必须是：

```
/var/www/ocr/
├─ index.html
├─ favicon.svg
└─ assets/
   ├─ index-*.js
   └─ index-*.css
```

上传前可先删除旧的 `assets/index-*.js|css`，避免残留旧文件。

> 压缩包已按 `/ocr/` 子路径构建：index.html 内引用的是 `/ocr/assets/...`、`/ocr/favicon.svg`。
> 路由使用 HashRouter，所以 `https://8.130.177.176:8088/ocr/#/m` 刷新不会 404，
> 静态服务器无需配置 SPA rewrite。

## 二、接口地址（.env.production）

当前构建的接口地址已按后端提供的信息配置为：

```ini
VITE_OCR_ENDPOINT=https://8.130.177.176:64435/api/ocr
```

> ⚠️ 网站是 `https://8.130.177.176:8088`，接口是 `http://`：
> 浏览器会以「混合内容」拦截 https 页面发起的 http 请求（控制台显示 Mixed Content，
> 请求不会发出）。前端已加了预检，界面会直接提示原因。
>
> 要真正可用，二选一：
>
> **方案 A（推荐）**：后端在 8088 的 Caddy 配置里加三行，把 `/api/*` 反代到
> `127.0.0.1:64435`，然后前端把 `.env.production` 改回 `VITE_OCR_ENDPOINT=/api/ocr`
> 重新构建（我可以直接改）。
>
> **方案 B**：后端给 64435 配 HTTPS 证书并允许跨域，把 `https://.../api/ocr` 地址给我，
> 只改 `.env.production` 重新打包即可。

`deploy/Caddyfile-8088.conf` 里已经写好方案 A 的完整配置。

## 三、验证方式（打开页面即可）

- 移动端：https://8.130.177.176:8088/ocr/#/m
- 管理端：https://8.130.177.176:8088/ocr/#/admin/files
- 接口诊断：https://8.130.177.176:8088/ocr/#/admin/diagnostics

若浏览器提示证书不受信任，是因为该 IP 使用自签名证书，选择“继续访问”即可。

```bash

# 重新打包：把 dist/ 内文件压缩成 zip 上传即可
```

部署路径、接口地址都在 `.env.production` 里改，无需动代码。
